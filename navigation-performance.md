# Fitted image caching and navigation cancellation

This change addresses repeated decoding while revisiting images and redundant
rendering work after a newer navigation request arrives. Keyboard input buffering,
frame transitions and neighboring image warming remain separate follow-up work.

## Completed Rust slice

`serve_media_path` repeatedly decoded and fitted an unchanged image, including
images just viewed. A process-local LRU now retains only fitted BMP surfaces,
bounded to 64 MiB and 64 entries. Lookup checks file size and modification time;
on Unix it additionally checks device, inode and change time. Atomic replacement,
deletion and viewport changes are covered through the public image-serving API.
Full-size originals, animation, transparency and color-profile fallback continue
through the existing paths. Registry authorization still precedes serving.

Superseded requests now check their navigation ticket between rendering stages.
A canceled fit cannot fall through to reading the original file. A decoder
already running finishes its current stage before cancellation takes effect.
The existing single decode gate continues to bound concurrent decoder memory.

## Objective measurements

Frozen baseline: Git commit `1dccf130d33beb83cad12aeb4930b1c264a72249`.
Same lockfile, compiler and release profile; 21 alternating process pairs. Each
process renders a six-image working set of 12 MP RGB JPEG/PNG images at 1280×768,
then requests it 120 times. Fixtures are generated by the existing rewrite
benchmark. Every repeated response must equal its own first-render bytes.

| Rust image-serving measurement | Baseline | Candidate |
| --- | ---: | ---: |
| Revisit median | 44.858 ms | 0.054 ms |
| Revisit p95 | 75.029 ms | 0.075 ms |
| First-render median | 47.537 ms | 49.254 ms |

Revisit p95 improves by 99.90%. First-render latency does not improve in this
slice. These are Rust serving measurements with a warm filesystem page cache;
they do not measure IPC, webview decode, compositor presentation or cold disk.
Raw observations are in `benches/navigation-results/paired.json`. The red
baseline fails the example's 16 ms median / 25 ms p95 frame-budget assertion;
the candidate passes. `benches/compare_navigation.py` requires at least 50%
p95 reduction and a candidate p95 below 25 ms.

Run with preserved baseline and current release example:

```sh
cargo build --release --locked --offline --manifest-path src-tauri/Cargo.toml --example navigation_bench
python3 benches/compare_navigation.py /tmp/manzar-navigation-baseline/navigation_bench src-tauri/target/release/examples/navigation_bench /tmp/manzar-rewrite-corpus benches/navigation-results/paired.json
```

For a clean reproduction, generate the corpus using `rewrite_bench prepare`.
Build the baseline in a checkout of the commit above after copying only
`src-tauri/examples/navigation_bench.rs` into that checkout. Preserve its
executable, then build the candidate with the same compiler and lockfile. The
example calls the public serving API and needs no baseline production changes.

## Remaining navigation work

Hypotheses to verify with real UI playback before changing the frontend:

1. Arrow events arriving during an IPC operation are dropped by the shared busy
   guard. A burst should reach the same final position as sequential presses.
2. Remounting the image removes the old frame before the next image is decoded.
   The viewer should retain visible pixels until the replacement is ready and
   should reject obsolete completions.
3. First-time sequence traversal still waits for decoding. Bounded neighboring
   image warming could improve this, provided it never supersedes foreground
   requests or loads oversized images, video, or unsuitable original fallbacks.

Follow-up work should reproduce the keyboard burst in the real React UI,
implement one failing test at a time and measure displayed switching separately
from Rust serving. Preserve destructive-action guards, opaque IDs, stale-file
invalidation, zoom and large-image approval behavior. These frontend and
first-visit improvements are not included in the current update.
